# Write a how-to guide

A how-to guide helps a reader who knows the basics to reach one real goal. The
reader has a problem and wants the steps, not a lesson. The source of this
guide is the Diátaxis page on
[how-to guides](https://diataxis.fr/how-to-guides/). The template is
[templates/how-to.md](../templates/how-to.md).

## What a how-to guide does

- It names the goal in the title. Use a verb and its object, for example
  "Rotate a credential". Diátaxis writes "How to rotate a credential"; pick one
  form for the repository and keep it.
- It lists the steps in the order that the reader does them. One step is one
  action.
- It assumes that the reader knows the tools and the vocabulary.
- It says how the reader checks that the goal is reached.
- It handles the real cases: a step that fails, and a choice that depends on
  the situation of the reader.

## What a how-to guide does not do

- It does not teach. A tutorial teaches.
- It does not explain why. A link leads to the explanation.
- It does not list every option of a command. A link leads to the reference.
- It does not describe more than one goal. Write a second guide.

## Checks before you publish

- Follow the steps on a clean state, and write down every step that you did
  but did not write.
- Read the title as a task that a person has. If nobody has that task, the
  guide is a tutorial or an explanation.
