# Write a tutorial

A tutorial is a lesson. The reader is new to the subject, does a task from
start to end, and learns by doing it. The writer is the teacher and owns the
result: if the reader follows every step, the tutorial works. The source of
this guide is the Diátaxis page on
[tutorials](https://diataxis.fr/tutorials/). The template is
[templates/tutorial.md](../templates/tutorial.md).

## What a tutorial does

- It says at the start what the reader builds.
- It gives one action per step, and shows the result of each action. The
  reader then knows that the step worked.
- It shows a visible result early, and often.
- It gives one path. It names no options and no alternatives.
- It says only as much about the reason for a step as the reader needs to
  continue. A link leads to the explanation.

## What a tutorial does not do

- It does not list facts. A link leads to the reference.
- It does not solve a real problem of the reader. That is a how-to guide.
- It does not assume knowledge that the reader may lack.

## Checks before you publish

- Run the tutorial from a clean state, on a machine that is new to it.
- Give the tutorial to a person who does not know the subject, and watch.
- Repeat the run when a tool in the tutorial changes its version.
